Если правильное решение coach-задачи может завершиться, не дочитав ввод
(`break` по первому совпадению), условие обязано это оговаривать: программа
читает ровно столько строк, сколько запросит, остаток вводить не нужно.

**Why:** 2026-08-06, задача «Первая ошибка в логе выкатки». Ученик при ручной
проверке не смог ввести все 4 строки лога — программа завершилась на третьей,
и он принял это за ошибку своего кода, а не за нормальное поведение потока
ввода. Дважды переспрашивал, пока причина не прояснилась.

**How to apply:** в блоке «Вход» — отдельная строка про ранний выход; в
примерах помечать `#`-комментарием строки, которые при таком вводе фактически
не читаются. Правило записано в
`study_python/coach-skill/references/task-design.md` («Ранний выход из чтения
ввода»). Связано с [[feedback-task-docstring-format]].
