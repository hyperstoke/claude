Инлайн-автодополнение кода в VS Code (серые подсказки-призраки, Copilot) отключено в user settings.json: `editor.inlineSuggest.enabled: false`, `github.copilot.enable.*: false`. Также отключён линтер/типчекер Python (Pylance): `python.analysis.typeCheckingMode: off`, `python.linting.enabled: false`.

**Why:** Пользователь учится программировать (первый язык — Python, ~2 месяца опыта) и не хочет, чтобы редактор дописывал код за него или подсвечивал ошибки во время обучения — это часть учебного процесса, [[user_python_beginner]].

**How to apply:** Оба правила и точные названия настроек продублированы в /Users/folder/Documents/claude/CLAUDE.md (пункты 7-8) — это основной источник правды для этого проекта. Claude может сам инициативно предложить включить обратно, если сочтёт нужным (например, когда подсветка ошибок реально пригодится) — но включает только после явного согласия пользователя, не самостоятельно и не молча.

**Обновление 2026-07-15:** обнаружено, что `python.analysis.typeCheckingMode` в реальном settings.json стоял на `"strict"` (не `"off"`, как ожидалось по этой памяти) — настройка где-то разошлась с намерением (возможно, обновление VS Code или случайный клик). Вернул в `"off"` по просьбе пользователя. Вывод: перед тем как полагаться на эту память, стоит сверяться с фактическим содержимым `~/Library/Application Support/Code/User/settings.json`, а не считать, что настройка держится сама по себе. Пользователь прямо попросил зафиксировать: включить типчекер обратно нужно будет, когда понадобится (естественный момент — этап 1 roadmap «ООП и продвинутый Python», где на очереди тайп-хинты, [[project_github_sync]] соседствует с этим же CLAUDE.md), либо раньше, если пользователь попросит явно.
