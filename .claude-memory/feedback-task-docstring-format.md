Денис попросил (2026-07-21) оформлять блок условия в файлах coach-задач
(`study_python/practice/coach_tasks/*.py`) тройными кавычками `"""..."""`
(как в `control_letter.py`), а не `#`-комментариями. 2026-07-22 подтвердил
расширение правила на файлы задач со Stepik (`study_python/practice/<NN>/...`)
тоже — применять при создании любого нового файла задачи.

**Why:** нагляднее и единообразнее при большом объёме текста условия;
формат уже прописан в `coach-skill/references/task-design.md` («Структура
файла задачи») — `#`-шапка была отклонением от собственного стандарта.
Правило и шаг создания файла продублированы в `study_python/CLAUDE.md`
(«Как проходит работа над задачей», п.2).

**How to apply:** докстринг в начале файла с условием задачи. Для coach-задач
— полная структура (Задача / Тема+Сложность / Легенда / Вход / Выход /
Примеры), для Stepik-задач — только применимые поля (без Темы/Сложности/
Легенды, они специфичны для coach-skill). Для курс-стайл файлов
(input()/print(), без def) безопасно: docstring при запуске ничего не
делает. В примерах вход/выход брать в кавычки, пояснения давать
`#`-комментарием — иначе аннотацию можно принять за требуемый вывод (Денис
так и сделал в задаче csv_unescape: `(экранировать нечего)` понял как
строку, которую надо печатать). Связано с [[review-style-soft-nudge]].
