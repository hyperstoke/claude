Бинарный поиск — искать в упорядоченных данных, каждый раз отбрасывая половину. Миллион элементов — 20 шагов вместо миллиона. Один и тот же механизм работает и для поиска элемента в отсортированном массиве, и для «угадай число». Ниже: канонический шаблон, визуализатор, оценка на худший случай и типовые баги.

Идея

Данные должны быть упорядочены. Смотрим на середину; ответ (меньше / больше / равно) сразу говорит, в какой половине искать дальше — вторая отбрасывается целиком. n → n / 2 → n / 4 → … → 1. Это O(log n): диапазон в миллион схлопывается за 20 шагов, в миллиард — за 30.

Канонический шаблон

bin_search(items, target)индекс или −1
def bin_search(items, target):
    left, right = 0, len(items) - 1
    while left <= right:
        mid = (left + right) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

Инвариант: если target есть в массиве, он всегда внутри отрезка [left, right]. Цикл идёт, пока отрезок не пуст (left <= right). Проверив mid, границу обязательно сдвигают за него — mid + 1 или mid - 1, — иначе отрезок не сузится. Предусловие: items отсортирован по возрастанию.

Визуализатор

Отсортированный массив. Выбери, что ищем, и шагай: подсвечены границы L / R, середина mid, отброшенные половины гаснут. Панель справа — активная строка кода.

def worst_case_steps(n):
    count = 0
    while n > 0:
        n //= 2

    return count

# симулируем и на каждом шаге уходим в ЛЕВУЮ половину:
right = mid - 1     # ← так остаётся МЕНЬШАЯ половина

    
Почему недосчёт: при mid = (left + right) // 2
      верхняя часть [mid + 1, right] не меньше нижней (на 1 больше, когда
      элементов в отрезке чётное число). Худший случай — когда тебя гонят в
      бо́льшую половину, то есть двигать надо left, а не
      right. Для n = 10 правильный ответ 4, а «всегда влево»
      даёт 3.

  


  
Типовые баги


  

    
∞left = mid вместо left = mid + 1

    
while left <= right:
    mid = (left + right) // 2
    if items[mid] < target:
        left = mid          # при right == left + 1 mid == left — отрезок не двигается

    
Границу всегда сдвигают за проверенный mid.
      Иначе на отрезке из двух элементов mid застревает на
      left — вечный цикл.

  


  

    
<left < right вместо left <= right

    
while left < right:   # отрезок из одного элемента не проверяется

    
С < одноэлементный отрезок
      [left, left] пропускается, и крайние значения не находятся.
      Правильно — left <= right.

Бинарный поиск не проверяет предусловие и на неупорядоченных

В реальном коде — bisect

  
Стандартный модуль: bisect_left(a, x) и bisect_right(a, x)
    возвращают позицию для вставки x, сохраняющую порядок;
    insort(a, x) вставляет с поддержанием сортировки. Написано на C,
    крайние случаи учтены.

  

    
contains(a, x)есть ли x в отсортированном a

    
from bisect import bisect_left

def contains(a, x):
    i = bisect_left(a, x)
    return i < len(a) and a[i] == x

  


  

    Бинарный поиск окупается на упорядоченных данных, которые редко меняются. Если
    данные постоянно обновляются и держать их отсортированными дорого — быстрее
    set / dict с доступом за O(1).
