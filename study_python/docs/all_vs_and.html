Две записи «выполнено всё сразу» дают одинаковый ответ, но по-разному относятся к работе: список внутри all() вычисляется целиком, а and останавливается на первом False. Пока условия независимы, разницы нет. Как только одно защищает другое — разница становится разницей между ответом и падением.

Четыре строки, из которых всё следует

В all() нет ничего волшебного: это обычный цикл с ранним выходом. Вот её полный эквивалент — и эквивалент сестры any().

all(iterable)все ли истинны
def all(iterable):
    for element in iterable:
        if not element:
            return False   # нашли ложный — обрываем цикл
    return True            # дошли до конца, ложных нет
any(iterable)есть ли хоть один
def any(iterable):
    for element in iterable:
        if element:
            return True    # нашли истинный — обрываем цикл
    return False           # дошли до конца, истинных нет
  • Аргумент один, и по нему идёт цикл. for element in iterable — внутрь подаётся одна последовательность: список, строка, кортеж, генератор, range. Поэтому all(a, b, c) через запятую — ошибка, а all([a, b, c]) — нет.
  • Останавливается сама. return False внутри цикла обрывает его немедленно. Ленивость у all() есть всегда — теряется она раньше, на построении списка, который ей передают.
  • Проверяет истинность, а не равенство True. В коде стоит if not element, поэтому ложными считаются 0, "", [], None — всё пустое. all([1, "текст", [0]]) → True, а all([1, 0, 3]) → False.
  • Пустой вход даёт True. Тело цикла не выполнится ни разу, управление сразу дойдёт до return True. У any([]) по той же причине False.

Одна проверка, две конструкции

Слева — версия со списком, справа — цепочка. Условия те же самые, в том же порядке; отличается только то, чем они склеены. Выбери артикул — увидишь, что вычислилось.

all([...])вычисляет всё
return all([
    len(code) == 7,
    code[:2].isalpha(),
    code[:2].isupper(),
    code[2] == "-",      # нужен len >= 3
    code[3:].isdigit(),
    int(code[3:]) > 0    # нужны цифры
])
andостанавливается
return (len(code) == 7
        and code[:2].isalpha()
        and code[:2].isupper()
        and code[2] == "-"
        and code[3:].isdigit()
        and int(code[3:]) > 0)
  • "AB-1234" — корректный. Обе версии проходят все шесть условий и отвечают True. Здесь конструкции неразличимы.
  • "1B-1234" — цифра вместо буквы. Ответ у обеих False, но список после провала на втором условии вычислил ещё четыре впустую. Ошибки нет — есть лишняя работа.
  • "" — пустая строка. Цепочка останавливается на длине. Список продолжает собираться и добирается до code[2], которого не существует, — IndexError.
  • "AB-a234" — буква в номере. Цепочка останавливается на isdigit(). Список доходит до int("a234") — ValueError. Проверка отработала правильно и всё равно не спасла: её результат никого не остановил.

Почему в «Good password» список был уместен

Тот же all([...]), и там он не был ошибкой — потому что ни одно из четырёх условий не зависит от остальных.

is_password_goodусловия независимы
return all([
    len(password) >= 8,                     # не упадёт никогда
    any(ch.isupper() for ch in password),   # цикл по пустой строке = False
    any(ch.islower() for ch in password),   # индексов нет — падать не на чем
    any(ch.isdigit() for ch in password)    # порядок можно тасовать как угодно
])

Ни одно условие не обращается к символу по индексу и не превращает строку в число. Любое из них можно вычислить на любом входе, включая "". В артикуле всё иначе: code[2] имеет смысл только если длина уже проверена, а int() — только если уже известно, что там цифры. Появилась зависимость — список перестал годиться.

Когда что писать

andОдно условие защищает следующее
return (len(code) == 7
        and code[3:].isdigit()
        and int(code[3:]) > 0)

Почему только так: and — единственная конструкция, которая физически не выполняет то, что правее первого False. Список сюда не годится ни в каком виде.

all(... for ...)Условие одно, объектов много
def is_prime(num):
    return num > 1 and all(num % i != 0
                           for i in range(2, int(num ** 0.5) + 1))

Почему не and: делителей заранее неизвестно сколько — цепочку руками не напишешь. Почему без []: список заставил бы перебрать весь диапазон даже после того, как делитель нашёлся.

all([...])Несколько независимых условий, написанных руками
return all([
    len(password) >= 8,
    any(ch.isupper() for ch in password),
    any(ch.islower() for ch in password),
    any(ch.isdigit() for ch in password)
])

Здесь это вопрос вкуса: цепочка and дала бы тот же результат и не вычисляла бы лишнего. Список выигрывает читаемостью — четыре требования стоят столбиком, как в условии задачи.

all() по даннымЧисло условий заранее неизвестно
required = ["host", "port", "user"]

def config_is_full(config):
    return all(key in config for key in required)

Почему только так: список требований может прийти из файла или вырасти завтра. and пишется руками, значит число звеньев зафиксировано в момент написания кода — здесь это невозможно.

ловушкаand возвращает операнд, а не True/False
name = ""
name and name.isupper()   # -> '' , а не False

orders = []
all(o["paid"] for o in orders)   # -> True: «все оплачены»,
                                 #    хотя заказов нет вовсе

Два разных сюрприза. and возвращает значение операнда, на котором остановился, — функция с аннотацией -> bool вернёт строку. all() всегда даёт строгий True/False, но на пустом входе этот True ничего не гарантирует.

Проверочный вопрос перед тем, как написать all([...]): могу ли я поменять условия местами и ничего не сломать? Да — список уместен, выбирай по читаемости. Нет — условия зависят друг от друга, и нужен and.
