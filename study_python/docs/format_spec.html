Фигурные скобки в f-строке — это не «дырка, куда подставится значение». Всё, что стоит после двоеточия, — отдельный мини-язык, который умеет выравнивать, дополнять нулями, группировать разряды, считать проценты и переводить в шестнадцатеричную систему. Знаешь его — и целые куски кода, которые обычно пишут циклами, исчезают.

Две части одной скобки

Внутри {} живут две независимые вещи, разделённые двоеточием: слева — что печатаем, справа — как.

f"{значение:спецификация}"что : как
total = 1234567.891

f"{total}"          # '1234567.891'  — без спецификации, как есть
f"{total:,.2f}"     # '1,234,567.89' — группировка + два знака
#   ^^^^^ ^^^^
#   что   как

Слева может стоять любое выражение: f"{a + b}", f"{items[0]}", f"{price * qty:,.2f}". Справа — строка по строгой схеме, и слоты в ней идут в фиксированном порядке.

Порядок слотов

[заполнитель][выравнивание][знак][ширина][группировка][.точность][тип]схема
f"{x:*>+12,.2f}"
#    │││  │ │  └─ тип: f=дробное, d=целое, %=проценты, e=экспонента, b/x/o=системы счисления
#    │││  │ └──── точность: сколько знаков после точки
#    │││  └────── группировка: , или _ — разделитель тысяч
#    ││└───────── ширина: минимальная длина поля
#    │└────────── знак: + всегда, - только минус, ' ' пробел вместо плюса
#    └─────────── заполнитель и выравнивание: < влево, > вправо, ^ по центру
  • Все слоты необязательны, но порядок менять нельзя. :,.2f — только группировка, точность и тип; :>10 — только выравнивание и ширина.
  • Заполнитель пишется перед выравниванием и без него не работает: :*>10 — забить звёздочками, :0>10 — нулями. Частный случай :010 (нули слева у чисел) — сокращение ровно для этого.
  • Ширина — минимальная, а не максимальная. Значение длиннее поля не обрежется, оно просто вылезет: в песочнице ниже посмотри на :010,.2f для большой суммы — там уже 12 знаков, и нули не добавились.
  • По умолчанию строки жмутся влево, числа — вправо. f"|{'abc':10}|" → |abc       |, а f"|{42:10}|" → |        42|. Нужно иначе — ставь < или > явно.

Песочница

Выбери значение — увидишь, что даёт каждая спецификация. Все результаты посчитаны настоящим Python, не пересказаны словами.

f"{значение:…}"спецификация → результат

Где это встречается в работе

:>14,.2fДеньги в отчётах, счетах, выгрузках
print(f"{'ТОВАР':<16}{'КОЛ-ВО':>8}{'СУММА':>14}")
for name, qty, price in rows:
    print(f"{name:<16}{qty:>8}{price * qty:>14,.2f}")

Что даёт: колонки сходятся сами, без ручных пробелов и без подсчёта длины имени. Каждая строка — одна инструкция вместо цикла добивки.

результатколонки сошлись
ТОВАР             КОЛ-ВО         СУММА
Клавиатура             3     14,970.00
Монитор 27            12    383,886.00
Кабель HDMI          140     48,860.00
ИТОГО                155    447,716.00
:06Идентификаторы и время — ведущие нули
f"ЗАКАЗ-{815:06}"        # 'ЗАКАЗ-000815'
f"{9:02}:{5:02}"         # '09:05'

Зачем в работе: номера документов фиксированной длины и время — это требование форматов обмена (банковские выгрузки, имена файлов, логи). Строки одинаковой длины ещё и сортируются правильно как текст: '000815' и '001200' встанут по порядку, а '815' и '1200' — нет.

:.1%Проценты — без ручного умножения на 100
done, total = 37, 120
f"{done / total:.1%}"    # '30.8%'

# без спецификации пришлось бы так, и легко ошибиться с округлением:
f"{round(done / total * 100, 1)}%"

Что даёт: % сам умножает на 100 и дописывает знак. Прогресс задач, конверсия, доля ошибок в мониторинге — везде, где доля превращается в проценты для человека.

:%d.%m.%YДата и время — вместо strftime
from datetime import datetime

d = datetime(2026, 9, 12, 14, 5)
f"{d:%d.%m.%Y %H:%M}"    # '12.09.2026 14:05'
f"{d:%Y-%m-%d}"          # '2026-09-12'

Почему это работает: спецификация — не универсальный синтаксис, а строка, которую Python отдаёт самому объекту (методу __format__). У чисел она значит «ширина и точность», у datetime — коды strftime. Один и тот же слот, разные типы — разный смысл.

{x=}Отладка — имя и значение одной записью
items, ratio = [1, 2, 3], 0.5
print(f"{items=} {ratio=}")   # 'items=[1, 2, 3] ratio=0.5'

Зачем: знак = печатает и выражение, и результат. Отладочный print перестаёт врать после переименования переменной — имя берётся из кода, а не из строки, которую забыли поправить.

:#x · :08bСистемы счисления — маски, цвета, протоколы
f"{255:#x}"     # '0xff'    — цвет, адрес, байт в дампе
f"{255:08b}"    # '11111111' — битовая маска прав доступа
f"{255:#o}"     # '0o377'

Где встретится: права доступа к файлам, флаги в конфигурации, разбор бинарных форматов, цвета в вебе. # добавляет префикс 0x/0b/0o, а 08 добивает нулями до полного байта — иначе 5 напечатается как 101, и разряды в столбце разъедутся.

:>{w}Ширина, известная только во время работы
w = max(len(name) for name in names)

for name in names:
    print(f"{name:>{w}} | {counts[name]:>6,}")

Что даёт: внутрь спецификации можно вложить ещё одни {} — ширина берётся из переменной. Так таблица подстраивается под данные: добавился длинный заголовок — колонка раздвинулась сама.

:, → пробелРусский формат чисел
f"{1234567:,}".replace(",", " ")   # '1 234 567'

Почему так: в русской типографике разряды разделяются пробелом, а слот группировки знает только , и _. Получаем группировку штатным способом и меняем разделитель одной заменой — это всё равно короче и надёжнее ручного цикла по тройкам.

Ловушки

ValueErrorГруппировка не работает со строками
f"{'1234567':,}"
# ValueError: Cannot specify ',' with 's'.

f"{int('1234567'):,}"   # '1,234,567' — сначала число, потом формат

Почему: «разряды» есть у числа, а не у последовательности символов. input() всегда возвращает строку, поэтому перед форматированием её нужно привести к числу. Это общее правило: приводи типы на границе ввода, дальше число должно быть числом.

{{ }}Как напечатать саму фигурную скобку
f"{{это не подстановка}} — {40 + 2}"
# '{это не подстановка} — 42'

Зачем нужно: когда из f-строки собирается JSON, шаблон конфигурации или CSS — там фигурные скобки часть текста. Удвоение — единственный способ сказать «это литерал».

:010Ширина не обрезает
f"{1234567.891:010,.2f}"   # '1,234,567.89' — уже 12 знаков, нули не добавились
f"{42:010,.2f}"            # '000,042.00'   — здесь поле шире значения

Что это значит на практике: ширина гарантирует минимум, а не фиксированный размер. Если колонка в отчёте обязана быть ровно N знаков, ширину надо брать с запасом по самому длинному значению — например, через вложенное {w} из примера выше.

Проверочный вопрос перед тем, как писать цикл по символам или ручную добивку пробелами: это точно про логику — или про то, как значение выглядит? Если про внешний вид (разряды, нули, ширина, проценты, система счисления, дата) — почти наверняка это один слот в {}, а не десять строк кода.
