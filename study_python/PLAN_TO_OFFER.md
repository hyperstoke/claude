# План до оффера: стажировка в крупной компании

Составлен 2026-07-24. Источник правды по срокам — даты из других файлов
(`coach/activity.json`, roadmap в `CLAUDE.md`) ссылаются сюда.

**Цель:** оффер на стажировку Python-backend в крупной компании
(Яндекс / Т-Банк / Авито / VK). Далее — junior-позиция по итогам стажировки.

**Вводные:** темп 25+ ч/неделю. Старт Python — май 2026, на 2026-07-24
пройдено 9 из ~15 разделов Stepik, 54 решённые задачи, регулярность 93% дней.

**Прогноз: оффер май–июль 2027 (10–12 месяцев).** Целевое окно — весенний
набор 2027. Запасное — осенний набор 2027 (старт января 2028), тогда 14–15
месяцев.

Ускорение от прошлого темпа (~10–12 ч/нед) взято 1,8x, а не 2,2x: скорость
упирается в усвоение, а не в часы. Это осознанно консервативная оценка.

## Календарь вех

### 1. Синтаксис Python: разделы 10–15 → к середине сентября 2026

Списки, кортежи, словари и множества, **функции**, исключения, файлы.

**Критерий готовности:** курс Stepik закрыт; функции пишутся без подсказок
(параметры, `return`, область видимости); словарь используется как рабочий
инструмент, а не «видел».

**Риск:** функции сейчас в блоке «не трогал» (`coach/known_topics.md`) — это
ворота ко всему остальному. Не откладывать: как только закрыты списки, брать
функции, даже если по порядку курса они дальше.

### 2. Git и терминал → сентябрь 2026 (параллельно, с этой недели)

Коммиты, ветки, история, разрешение конфликтов; базовая работа в терминале.

**Критерий готовности:** свой публичный репозиторий с решениями, коммиты
делаются самостоятельно, без Claude.

**Почему сейчас, а не «позже»:** на отборе смотрят историю коммитов, а она
копится месяцами. Репозиторий, начатый в сентябре 2026, к марту 2027 выглядит
как полгода регулярной работы. Начатый в марте — как пустой.

### 3. ООП и продвинутый Python → конец октября 2026

Классы, наследование, магические методы; comprehensions, декораторы,
генераторы, context managers, `itertools`/`functools`.

**Критерий готовности:** свой класс с несколькими методами написан с нуля;
понятно, *когда* класс нужен, а когда достаточно функции.

### 4. SQL: SQLite → PostgreSQL → конец ноября 2026

CRUD, проектирование схем, JOIN'ы, индексы (обзорно).

**Критерий готовности:** схема из 3–4 связанных таблиц спроектирована
самостоятельно; JOIN пишется без подглядывания.

**Почему до фреймворка:** реальные стажёрские вакансии просят «Python + SQL +
FastAPI» именно в таком порядке (`research/python-backend-trends_2026-07-15.md`).

### 5. Тестирование: pytest → середина декабря 2026

**Критерий готовности:** привычка писать тест к своему коду до того, как
код объявлен готовым.

### 6. Алгоритмы и структуры данных → март 2027 (параллельно, с января)

**Это главный этап для цели «стажировка».** 5–7 ч/неделю на протяжении
трёх месяцев, параллельно с этапами 7–8.

Программа: сложность O(n) (уже начато — есть интерес сам по себе), массивы и
строки, два указателя, хеш-таблицы, стек/очередь, бинарный поиск, сортировки,
рекурсия, деревья и графы (обзорно — до BFS/DFS).

**Критерий готовности:** ~200 задач уровня easy–medium; medium решается за
25–35 минут; из 4 задач за 2 часа стабильно закрываются 3.

Отдельно про **скорость под таймером** — см. раздел ниже.

### 7. FastAPI, REST и аутентификация → начало февраля 2027

Роуты, Pydantic-модели, async/await, проектирование API, JWT.

**Критерий готовности:** сервис с 5–6 эндпоинтами, работающий с БД из этапа 4,
с тестами из этапа 5.

### 8. Пет-проект, Docker, деплой → середина марта 2027

Кандидат № 1 — чат-бот с долговременной памятью на mem0 (см. `CLAUDE.md`).
Контейнеризация, выкладка в облако, README.

**Критерий готовности:** проект доступен по ссылке и работает; в README есть
описание архитектуры и инструкция по запуску.

### 9. Отбор → готовность март–апрель 2027, оффер май–июль 2027

Этапы отбора обычно: заявка → онлайн-тест по алгоритмам → 1–2 технические
секции → финал. Суммарно 1–3 месяца.

## Окна набора на стажировки

Наборы обычно идут двумя волнами:

- **весна** — заявки март–май, старт июнь–июль. **← целевое окно 2027**
- **осень** — заявки сентябрь–октябрь, старт декабрь–январь. ← запасное

Что проверить **до** того, как строить подготовку под конкретную компанию:

- **Студенческий статус.** Часть программ (не все) берёт только студентов или
  выпускников последнего года. Это может отсечь конкретные компании — узнать
  заранее, а не в момент подачи.
- Точные даты набора: они сдвигаются год от года, ориентироваться на прошлый
  год можно только приблизительно.
- Формат онлайн-теста конкретной компании (число задач, время, платформа).

Проверять ближе к декабрю 2026 — данные годичной давности к тому времени
устареют.

## Тренировка скорости под таймером

**Главный фильтр отбора — онлайн-тест на время.** Он режет большинство
кандидатов, и знание материала само по себе его не проходит.

Прямой сигнал уже есть: раздел 8 Stepik («Итоговая работа на циклы») не был
засчитан не из-за пробелов, а потому что не хватило 240 минут экзамена.
Задачи были решены — не хватило скорости. На отборе это ровно та же ситуация,
только без второй попытки.

Поэтому скорость — отдельная дисциплина, а не побочный эффект практики:

- С января 2027 — одна тренировка в неделю в формате теста: 4 задачи, 2 часа,
  таймер, без подсказок и без Claude.
- Фиксировать не только «решил/не решил», но и время на задачу. Цель — видеть
  тренд, а не разовый результат.
- Разбирать не только нерешённые задачи, но и решённые слишком долго.

В плюс работает то, что интерес к асимптотике (O(n), O(n²)) появился сам,
без внешнего требования — для алгоритмических секций это сильная стартовая
позиция.

## Главный риск

Не скорость обучения, а **разрыв «решаю задачки → делаю проект»**. Здесь
застревает большинство самоучек: задачи с курса решаются уверенно, а перед
пустым файлом проекта наступает ступор.

Лечение заложено в план: Git с сентября 2026 (а не «когда будет что заливать»),
проект на этапе 8 как обязательная веха, а не «если успею».

Второй риск — выгорание на 25+ ч/неделю. Регулярность 93% дней уже достигнута
на меньшем темпе; при просадке лучше снизить часы, чем прерывать серию.
Пропущенная неделя стоит дороже, чем месяц половинной нагрузки.
