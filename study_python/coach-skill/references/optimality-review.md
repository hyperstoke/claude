# Проверка оптимальности решения

## Правило №1: сравнивать только с изученным

Вердикт «неоптимально» допустим только если более идиоматичное решение
использует конструкции из `known_topics.md`. Иначе решение считается
оптимальным *для текущего уровня*, а недостающая конструкция — кандидат
на упоминание вида «скоро на курсе будет X, оно здесь идеально ляжет»
(без разбора, одной строкой).

## Типовые пары «топорно → идиоматично»

Проверять решение против этого списка (флагом — только изученное):

| Топорно | Идиоматично | Нужно знать |
|---|---|---|
| разворот строки циклом | `s[::-1]` | срезы |
| `for i in range(len(s)): s[i]` | `for ch in s:` | итерация по строке |
| счётчик вручную в цикле | `s.count(x)` | методы строк |
| поиск подстроки циклом | `x in s`, `s.find(x)` | оператор in / методы |
| конкатенация строк в цикле | `"".join(parts)` | join |
| `if flag == True:` | `if flag:` | булев тип |
| цепочка if по символам | `ch in "aeiou"`, `s.isdigit()` | in / str-методы |
| ручное отслеживание max/min | `max()`, `min()` | встроенные функции |
| `s.lower() == s_lower.lower()` повторно | вычислить один раз | переменные |
| индекс + счётчик вручную | `enumerate()` | enumerate |
| временный список для суммы | `sum()` | встроенные функции |

Список не исчерпывающий — это калибровка строгости. Общий вопрос этапа:
«решил бы так опытный питонист, зная ровно те же конструкции?»

## Как сообщать вердикт

Неоптимально — говорить конкретно и без готового кода:

1. Что именно топорно (строка/фрагмент).
2. Какая изученная конструкция здесь уместнее (назвать, не написать
   решение целиком).
3. Почему она лучше: читаемость, меньше мест для ошибки, скорость,
   так пишут в продакшене.
4. Предложить переписать самому и прислать снова.

Grade за неоптимальное, но рабочее решение — 3. Если пользователь после
объяснения осознанно оставляет свой вариант — не давить, зафиксировать 3
и перейти к ревью.

## Чего не делать

- Не выдумывать претензии ради строгости: короткое ясное решение циклом
  там, где среза/метода не существует, — оптимально.
- Не смешивать этот этап с код-ревью (PEP8, имена, докстринги — этап 3).
- Не понижать grade за стиль — только за выбор конструкции.
