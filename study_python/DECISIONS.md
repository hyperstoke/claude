# Решения по процессу обучения — почему правила такие

Обоснования правил, которые живут в `CLAUDE.md` и `coach-skill/SKILL.md`.
Вынесено 2026-09-09: сами правила должны быть в контексте всегда, а история
их появления — только когда кто-то спрашивает «почему так» или собирается
правило менять.

**Читать:** при вопросе «почему это правило такое», перед отменой или
переписыванием любого правила, при разборе спора о процессе.
**Не читать:** в обычной работе над задачами.

---

## Запись прогресса — по просьбе, а не по факту

*2026-08-26, прямое требование ученика.*

Раньше стояло «писать СРАЗУ»: после каждой проверенной задачи Claude правил
журнал и перезаливал страницу. Лишние действия и сожжённые токены на ответ
«проверь код». Триггером стала просьба пользователя, а не изменение
прогресса. Проверка задач, ревью и разбор в это не входят — они идут как
обычно, просто без записи.

## Оценка после каждого ревью, включая задачи со Stepik

*2026-08-27.*

До этого оценки писались только для coach-задач. Coach-задач не было три
недели — и все 8 тем в `progress.json` оказались просрочены на 18–37 дней.
Курсовые задачи составляют ~90% работы, значит именно они должны кормить
интервальное повторение.

Тему называть так же, как уже существующие в `progress.json`, чтобы не
плодить синонимы.

## Лимит на `note` в журнале — 600–800 знаков

*2026-08-27.*

Заметки разрастались до 7000 знаков на день, дублируя разбор из чата: файл
`activity.json` распух до 124 КБ, на сайте такую простыню в тултипе никто не
читает, и каждая запись стоила токенов. Подробности живут в коде и в истории
git. Старые длинные заметки не трогать — правило работает вперёд.

## Лимит на `reason` в очереди закрепления — 400 знаков

*2026-08-27.*

Та же болезнь, что у `note`: поля разрастались до 2900 знаков, файл — до
28 КБ. Хронологию попыток не пересказывать, она в журнале.

## Сроки у записей очереди закрепления

*Решение ученика 2026-08-06.*

Сроки нужны, чтобы очередь не выглядела бессрочным списком. Отдельного поля
`due` в JSON нет: правило зашито в `roadmap_artifact.html` (функции
`pqAllowance`/`pqDue`), дата считается в браузере, поэтому статус не
устаревает между сборками. Запас по `difficulty`: 0–2 → 3 дня, 3–5 → 7 дней,
6+ → 14 дней.

## Подсветка ошибок включена, Ruff — линтер, а не форматтер

*Выключалась на старте обучения, включена обратно 2026-08-16 по просьбе
ученика.*

Сначала волнистые линии мешали. Сейчас в user `settings.json`:
`python.analysis.typeCheckingMode: "basic"` (Pylance ловит опечатки в
именах, неверные аргументы, несовместимые типы) плюс расширение
`charliermarsh.ruff` — **только как линтер**:
`"[python]": {"editor.formatOnSave": false}`.

Решение осознанное: PEP8-замечания (пустые строки перед `def`,
неиспользуемые переменные) ученик правит руками. Автоформат молча прятал бы
их и обесценивал ревью. Ruff как форматтер можно предложить позже, когда
PEP8 перестанет быть учебной темой.

Мёртвая настройка `python.linting.enabled` удалена — в современном
расширении Python её больше нет.

## Отступы фиксированы в настройках репозитория

В `.vscode/settings.json` — `editor.detectIndentation: false`,
`editor.tabSize: 4`, `editor.insertSpaces: true`. Без этого VS Code
*угадывает* размер отступа по содержимому открытого файла и после `for ...:`
вставляет случайное число пробелов.

Образцом для угадывания служили именно строки внутри докстрингов,
выровненные под двоеточие. Отсюда правило писать многострочные блоки
докстринга flush-left.

## Инлайн-автодополнение отключено

В user `settings.json`: `editor.inlineSuggest.enabled: false`,
`github.copilot.enable.*: false`. Ученик учится сам и не хочет, чтобы
редактор дописывал код за него. Claude может предложить включить обратно,
но только после согласия — не молча.

## Эталонные файлы удаляются после разбора

Файлы `<slug>_reference.py` и прочие показательные примеры живут только до
конца работы над задачей. В репозитории должен копиться код ученика, а не
готовые решения рядом с ним: чужой код под рукой обесценивает собственную
попытку при следующем заходе на ту же тему.

## Наводящие вопросы выключены по умолчанию

Ученику они кажутся слишком очевидными и навязчивыми. Проверять код и по
делу указывать на ошибки — да; «а как думаешь, с чего начать» — нет. Для
конкретной задачи можно предложить включить такой формат, но не включать
самостоятельно.
