## Визуальная версия (Artifact)
Опубликована как интерактивная HTML-страница: https://claude.ai/code/artifact/bcc6e565-ce8e-44e3-b7ff-3b0116841593
(URL сменился 2026-08-11: редеплой на прежний адрес
`77cd3cee-37f1-43c9-98a7-1c71a9fed8e1` с Mac заблокирован — сессия видится как
посторонний читатель, список артефактов пуст. Старая страница осталась с
данными по 9 августа.)
Исходник — `study_python/roadmap_artifact.html` (в репо). Это приложение с
боковой панелью и четырьмя видами: **Обзор** (стрик со значками-молниями по
уровню, рекорд, счётчик задач, плитка «до ближайшего этапа», карточка «Общий
прогресс» = взвешенный % пути к стажировке + таймлайн всех этапов с датами
вех (у параллельных — пометка «параллельно», внизу строка финиша: подача
заявки и окно оффера), акцент-карточка «Далось труднее всего»
(авто-вывод самой сложной задачи из очереди), крупный мини-heatmap со сводкой
за 5 недель, короткая лента «Последняя активность» на 3 дня + ссылка в
Календарь), **Календарь** (heatmap дней занятий; будущие дни — пустые клетки,
текущий день — лавандовая обводка; клик по дню открывает детали со списком
задач — интенсивность подписана **словом** («обычная сессия», «плотная сессия»,
«большой день»), не «L2»; клик по задаче — модалку с её кодом (подсветка
синтаксиса + номера строк, один скролл) + ссылку на GitHub; ниже — полная лента
«Последние решённые задачи»), **Дорожная карта** (этапы 0–10, у каждой
карточки — дата вехи, конспекты тем в модалках) и **Закрепление** (сверху блок «Ждут решения» — приоритет; ниже —
закрытое, свёрнутое по темам-тегам `theme`; у каждой задачи сложность 0–10 с
прилагательным и «код ›»; плитка «ждут решения» прокручивает к блоку; третий
блок «Повторения по расписанию» — список уже решённых плановых SM-2-повторений
(из `ACTIVITY`, `kind: "повторено"`), отдельно от очереди `practice_queue.json`
— это другая система, за неё отвечает `progress.json`/`update_schedule.py`)
и **Документация** (карточки статей-разборов; клик открывает статью в той же
выезжающей панели, что и код задач — со страницы никуда не уходим).

**Раздел «Документация» (добавлен 2026-08-30).** Статьи живут в
`study_python/docs/`: `INDEX.json` — список (`id`, `title`, `subtitle`,
`date`, `tag`, `file`, `interactive`), рядом — по HTML-файлу на статью.
Файл статьи — **фрагмент**, не целая страница: корневой `<div class="doc-article">`
и разметка на классах `doc-*`, которые уже описаны в стилях сайта; своей
`<style>` у статьи нет и быть не должно. Python-код внутри пишется обычным
текстом в `<pre class="doc-code" data-py>` — подсветку при открытии наводит
`highlightPython()` сайта, дублировать её не нужно. Если статье нужен
интерактив, он не живёт в её файле (скрипты из `innerHTML` не выполняются):
функция кладётся в объект `DOC_INIT` в скрипте сайта, а в `INDEX.json`
указывается её ключ в поле `interactive` (у обычных статей — `null`).
`build_site.py` собирает всё это в константу `DOCS`. **Чтобы добавить статью:**
положить файл в `docs/`, дописать запись в `INDEX.json`, прогнать
`build_site.py` — HTML сайта руками не трогать.

**Общий прогресс** считается из блока `progress` в `coach/activity.json`
(этапы roadmap с весами, статусами `done|current|todo` и `sub_pct` текущего):
общий % = Σ(вес завершённых) + вес_текущего × sub_pct/100. Обновлять статусы и
`sub_pct` по мере продвижения. Мини-полоса на «Дорожной карте» синхронизируется
с этим % автоматически. Там же у каждого этапа — `deadline` (дата вехи из
`PLAN_TO_OFFER.md`, `null` = вне плана) и необязательный `parallel: true`;
блок `progress.finish` задаёт строку финиша. Отдельного блока `deadline`
верхнего уровня больше нет — ближняя цель по разделу Stepik с сайта убрана.
**Только тёмная тема** — чёрный фон + фиолетовый акцент (светлая отключена
по просьбе ученика, `data-theme` из скелета игнорируется).

**Сборка — только через скрипт, не руками.** Константы `ACTIVITY`,
`PRACTICE_QUEUE`, `PROGRESS`, `TRACKING_SINCE`, `DOCS` в HTML
**генерируются** `coach-skill/scripts/build_site.py` из `coach/activity.json` и
`coach/practice_queue.json` (между маркерами `/* @gen:start … @gen:end */`,
их не трогать). Скрипт заодно **вшивает код** каждой задачи в страницу (в т.ч.
код задач очереди закрепления по полю `file`) —
опубликованный артефакт на claude.ai не имеет доступа к локальным `.py`,
поэтому код должен лежать прямо в HTML. Порядок: `git pull` → правим JSON →
запускаем `build_site.py` (рабочим Python из [[python-interpreter-path]]) →
редеплой на тот же URL (не создавать новый артефакт; favicon 🐍 не менять).

**Перезаливка — с `force: true`, без вычитывания опубликованной страницы**
(разрешение дано пользователем 2026-08-27, действует постоянно). Причина:
инструмент публикации требует прочитать текущую версию целиком — это 440 КБ
и ~90 тысяч токенов на каждую публикацию, при том что страница целиком
генерируется скриптом из JSON, лежащего в git. **Обязательное условие —
`git pull` перед сборкой:** только он защищает от потери версии,
опубликованной с другого устройства. Без свежего pull `force` не применять.

Мобильная
раскладка полагается на `<meta viewport>` из скелета артефакта — при
локальном превью через http.server его нет, это нормально.


## Идеи для сайта (отложенные)

### Вкладка «Сортировки» — визуализация + трекер реализаций
Записано 2026-08-09 по просьбе ученика. Пятая вкладка в
`roadmap_artifact.html`: список алгоритмов сортировки, у каждого —
анимация на маленьком массиве, отметка «код написан / не написан» и
ссылка «код ›» на собственный файл ученика (как в модалках вкладки
«Закрепление»). Смысл — не картинка, а трекер: ученик пишет свою
реализацию каждого алгоритма, вкладка показывает, что уже закрыто.

Состав — все 11 алгоритмов, тремя группами (разбивка ученика):
- **Медленные:** пузырьком, выбором, простыми вставками.
- **Быстрые:** Шелла, быстрая, слиянием, пирамидальная, TimSort.
- **Не основанные на сравнениях:** подсчётом, блочная, поразрядная.

У каждой карточки — пометка глубины, они разные и путать их не надо
(оценка от 2026-08-09, под цель «алгоритмический тест на стажировку»):
- *писать руками* — пузырёк, выбор, вставки, быстрая, слиянием;
- *знать идею и сложность* — Шелла, пирамидальная, TimSort (плюс факт,
что за `sorted()`/`.sort()` стоит именно TimSort: гибрид вставок и
слияния, стабильный, O(n log n) в худшем случае);
- *знать, что существуют и когда применимы* — подсчётом, блочная,
поразрядная (обходят границу O(n log n), потому что не сравнивают
элементы, а раскладывают по корзинам; нужен ограниченный диапазон).

Референсы визуализаций (проверены 2026-08-09, все живые): основной —
[visualgo.net/en/sorting](https://visualgo.net/en/sorting) (свой массив,
пошаговый режим, подсветка текущей строки псевдокода; есть пузырёк,
выбор, вставки, слиянием, быстрая, подсчётом, поразрядная); дополняет
его [страница Галлеса](https://www.cs.usfca.edu/~galles/visualization/Algorithms.html)
(там Шелла, блочная, подсчётом). Проще всех —
[sortvisualizer.com](https://sortvisualizer.com/); с привязкой к коду —
[algorithm-visualizer.org](https://algorithm-visualizer.org/).

Данные — новый `coach/sorting_algorithms.json`, константа в HTML
генерируется `build_site.py` по образцу `PRACTICE_QUEUE`, код вшивается
по полю `file`. Тёмная тема и favicon 🐍 не меняются, редеплой на тот же
URL.
